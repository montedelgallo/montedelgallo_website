# MDG Site — Plan 3: SEO, Redirects & Launch Readiness — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Take the content-complete bilingual site from Plan 2 to launch-ready: every old WordPress URL answers with a real 301, search engines get a correct bilingual sitemap and structured data, pages share well, visits are measured without cookies, MotioForge downloads survive the cutover, and a tested deploy pipeline + launch runbook exist.

**Architecture:** Same Jekyll + `jekyll-polyglot` site on branch `site/foundation-home`. Redirects, analytics, downloads and the Soshiki embed are **data/config-driven** (`_data/redirects.yml`, `_data/site_meta.yml`) so the host choice only changes the deploy step. The build emits host-ready redirect files for both nginx and `_redirects`-style hosts; a GitHub Actions deploy job publishes `_site` to the chosen host. The 3,800-line check script is first split into focused Ruby modules so every later task adds its checks in one obvious place.

**Tech Stack:** Jekyll 4.4, jekyll-polyglot 1.14, SCSS, Ruby (checks), html-proofer, GitHub Actions, Lighthouse CI, cwebp/libvips (image variants). Host-dependent: Cloudflare Pages *or* Netlify *or* the existing nginx (see Decisions).

**Spec:** `tasks/2026-10-16-mdg-site-design.md` (§8 build, §9 integrations, §10 migration, §13 open items). Ledgers with the deferred items this plan picks up: `.superpowers/sdd/2026-10-16-01-foundation-home/progress.md`, `.superpowers/sdd/2026-10-16-02-pages-migration/progress.md`.

## Global Constraints

- Everything from Plans 1–2 still binds: EN root / IT `/it/` via polyglot, `page_id` pairing, bare permalinks, no `/it/it/`; real content only; Foundry tokens; AA; responsive; no include `assign`s `t`/`lang`/`p`; `JEKYLL_ENV=production bash script/check-build.sh` green after every commit.
- **No URL may be lost:** every URL in `tasks/wp-inventory.json` stays a built page or a `redirects.yml` entry (the standing check from Plan 2), and every `redirects.yml` entry must be emitted as a real HTTP 301 by the chosen host.
- **No cookies without consent:** nothing added may set a non-essential cookie or call a third-party tracker; analytics must be cookieless. No consent banner is introduced.
- **Host-agnostic build:** the static output plus generated redirect/header files must work on any of the D1 options; host-specific bits live only in the deploy job and its config files.
- **Drafts stay drafts:** pages with `noindex` (legal drafts) stay out of the sitemap and structured data until their real text lands.
- Git: author **Giovanni Panasiti <giova.panasiti@gmail.com>**, **no Claude/AI attribution**; `.superpowers/` never committed; targeted `git add`.

## Review Focus

- **Redirect loops or chains:** a `from` that is also a `to`, or a redirect to a URL that itself redirects → T2 asserts no loops and max one hop.
- **Sitemap/hreflang drift:** a page in the sitemap that is `noindex`, missing its IT/EN alternate, or listed without the `/it/` prefix → T3.
- **Invalid structured data:** JSON-LD that doesn't parse, or claims facts not on the page (ratings, prices, addresses beyond the company facts) → T4 parses every block and pins allowed types/props.
- **Analytics leaking or breaking pages:** the analytics script setting cookies, loading when unconfigured, or a blocked script breaking the booking CTA → T7.
- **Deploy publishing a broken site:** deploying when the check fails, or a preview deploy indexed by search engines → T11 deploy gated on the check; previews `noindex`.
